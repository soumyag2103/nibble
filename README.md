# Nibble — Baby First Foods Tracker

> Big milestones start with tiny bites.

Track your baby's solids journey with AI-powered guidance. Two phases: a Telegram bot first, then a full web app.

---

## What it does

Nibble helps parents introducing solids (6–12 months) track what the baby eats, learn their reactions, get week-by-week food suggestions, and log milestones and growth.

---

## The five tabs

**🍼 Today**
Shows today's 3 meal slots (Morning Snack, Lunch, Afternoon Snack). Each slot has a food suggested from this week's plan, reaction buttons (😍😊😐😖) that log to a daily file, and a "Change" button that fetches AI-generated variants — picking one PATCHes the week plan directly.

**💬 Chat**
Uma (AI persona) — parent chats freely. Uma can answer questions about baby food, suggest food swaps (emits a structured block that renders a confirmation card), and log meals or milestones via intent detection.

**📅 Plans**
Week-by-week food roadmap for months 6–12, generated by Gordon from `FOOD-ROADMAP.json`. Shows current week highlighted. All edits from the Today tab or Chat reflect here immediately — same source file.

**⭐ Milestones**
Log developmental milestones (first words, crawling, etc.). Uma detects milestone mentions in chat and auto-logs via action card.

**📊 Progress**
Appointments tracker, growth chart (WHO percentile curves via Chart.js), Foods Tried (reads `FOODS-TRIED.md` as base + log reactions overlaid), and Rejected Foods.

## Data flow

```
Onboarding → BABY-PROFILE.json (name, DOB, dietary, slots)
     ↓
init() → GET /api/ensure-week-plan
     ↓ (generates if missing via Groq AI)
WEEK-PLANS.json  ←── single source of truth
     ↓              ↑
Today tab reads    PATCH /api/week-plan/:m/:w/day/:d/slot/:s
Plans tab reads    (variant swap OR chat suggestion confirmed)
```

`WEEK-PLANS.json` is the only editable source for what the baby eats. Today tab and Plans tab always show the same data. All changes write back to it directly.

---

## AI agents

Three agents, all powered by Groq `llama-3.3-70b-versatile`:

| Agent | Persona | Role |
|-------|---------|------|
| Gordon | Food expert | Generates roadmap, week plans, meal variants |
| Uma | Warm parenting companion | Chat, intent classification, food swap suggestions |
| Meredith | Milestone tracker | Logs milestones from chat |

Each agent has a `SOUL.md` (system prompt) in `agents/<name>/`.

---

## Storage — file-based, no database

| File | What |
|------|------|
| `agents/profile/BABY-PROFILE.json` | Baby's name, DOB, diet, meal slots |
| `agents/gordon/FOOD-ROADMAP.json` | 6–12 month food curriculum (read-only) |
| `agents/gordon/WEEK-PLANS.json` | 7-day meal plans — single editable source |
| `logs/YYYY-MM-DD.json` | Daily meal logs with reactions |
| `agents/gordon/FOODS-TRIED.md` | All introduced foods (pre-onboarding + logged) |
| `agents/appointments/APPOINTMENTS.json` | Doctor visits |
| `agents/growth/GROWTH.json` | Height/weight entries |
| `agents/meredith/MILESTONE-ACHIEVEMENTS.json` | Logged milestones |

## Phase 1: Telegram Bot (`bot/`)

WhatsApp-style chat interface for real-time logging from the phone.

```
bot/
├── bot.js          # Grammy bot — message handler + agent routing
├── .env            # TELEGRAM_TOKEN, GROQ_API_KEY
├── package.json
└── start.bat       # Windows launcher
```

**Run:** `cd bot && node bot.js`

Features:
- Message any agent by name prefix (`gordon`, `meredith`, `bailey`) or free text
- Keyword routing: food words → Gordon, milestone words → Meredith, health words → Bailey
- Reads and writes shared `agents/` data files
- File update protocol: agents emit `<file_update>` blocks, bot applies them

---

## Phase 2: Web App (`web/`)

Full-featured browser app. Runs locally at `http://localhost:3001`.

```
web/
├── server.js       # Express API + Groq agent calls
├── public/
│   └── index.html  # Single-file vanilla JS app (no build step)
├── package.json
└── start.bat       # Windows launcher
```

**Run:** `cd web && node server.js`

## Shared: Agents + Data (`agents/`)

Both phases read/write the same agent memory and data files.

```
agents/
├── profile/
│   └── BABY-PROFILE.json       # name, dob, gender, dietary, meal slots
├── gordon/                     # Food + nutrition agent
│   ├── SOUL.md                 # Gordon's personality + rules
│   ├── FOODS-TRIED.md          # Running list of introduced foods
│   ├── FOODS-AVOIDED.md        # Foods to skip and why
│   ├── RECENT-MEALS.md         # Last ~14 days of meals
│   ├── PREFERENCES.md          # Texture stage, dietary notes
│   ├── FOOD-ROADMAP.json       # Long-term food introduction plan (read-only)
│   └── WEEK-PLANS.json         # Generated week-by-week meal plans (editable)
├── meredith/                   # Developmental milestones agent
│   ├── SOUL.md
│   ├── MILESTONE-MASTER.md     # WHO/AAP benchmark definitions
│   ├── MILESTONE-LOG.md        # Free-text milestone observations
│   └── MILESTONE-ACHIEVEMENTS.json  # Classified + dated achievements
├── bailey/                     # Doctor appointments agent
│   ├── SOUL.md
│   ├── QUESTIONS-QUEUE.md      # Pending questions for pediatrician
│   └── VISIT-LOG.md            # Post-visit notes + answers
├── appointments/
│   └── APPOINTMENTS.json       # Appointment dates + questions
└── growth/
    └── GROWTH.json             # Height + weight measurements over time
```

## Daily Logs (`logs/`)

One file per day. Written by the web app; readable by both phases.

```
logs/

```
